# MIX-STQ v0.23 실벤치마크 시도: 토큰 예산이 측정을 막았고, 끝난 문항에서는 차이가 없습니다

**작성일** 2026-08-31
**정정 (v25)** 이 시도의 IQ3 팔도 저장 불가능한 근사 인코더였습니다. 완주한
64문항의 동률은 편향된 부분집합 관측이며, 참조 IQ3 정확도나 배포 성능을
뒷받침하지 않습니다. `docs/mix-stq-v25-reference-iq3.md` 참조.

**결론** 자유형식 GPQA Diamond를 공식 프로토콜로 재현하려 했으나 **max_new_tokens를
2048로 잡아 실패했습니다.** 공식 설정은 32,768입니다. 사고 모드가 답에 도달하기 전
잘려 응답의 60%가 파싱 불가였습니다. 다만 **추론을 완주한 64문항에서 BF16과
IQ3_XXS가 61/64 = 0.9531로 정확히 동일**하며 불일치도 2 대 2로 대칭입니다.
이 부분집합은 편향돼 있으므로 확증이 아니라 정황 증거입니다.

---

## 1. 목표와 설계

v22는 로그 확률 채점으로 IQ3_XXS가 BF16과 구별되지 않음을 보였습니다. 그러나
그 방식은 **공식 수치가 만들어진 방법이 아니므로** 모델 카드의 값과 직접 비교할 수
없었습니다. 자유형식 생성이 공정한 비교입니다.

모델 카드에서 확인한 BF16 공식 수치(측정값 아님, 인용):

| 벤치마크 | Qwen3.8-27B BF16 |
|---|---:|
| Terminal Bench 2.1 (Terminus) | 73.0 |
| **GPQA Diamond** | **89.2** |
| LiveCodeBench v6 | 90.3 |
| SWE-bench Pro | 61.7 |
| HLE | 30.8 |

GPQA Diamond를 고른 이유는 198문항 4지선다라 생성 후 letter 추출이 가능하고,
Terminal Bench·SWE-bench 계열은 **Claude Code 하네스에 8시간 타임아웃, 256K
컨텍스트**를 요구해 이 연구 범위에서 재현 불가능하기 때문입니다.

## 2. 결과: 실패한 부분

| 팔 | bpw | 정확도 (198 기준) | 미파싱 |
|---|---:|---:|---:|
| dense (bf16) | 16 | 0.3687 (73/198) | **118 (60%)** |
| dense_iq3 (IQ3_XXS) | 3.0625 | 0.3384 (67/198) | **126 (64%)** |

**공식 89.2와 비교 불가합니다.** 0.3687은 모델의 능력이 아니라 토큰 예산의 한계를
측정한 값입니다.

원인은 확정적입니다. 모델 카드가 명시한 공식 조건은 `max_tokens=32,768`이고
`reasoning_effort`는 `xhigh`가 기본값입니다. 제가 사용한 2048은 **공식의 1/16**로,
GPQA Diamond의 대학원 수준 물리·화학 문제에서 사고 블록이 `\boxed{}`에 도달하기
전에 잘립니다.

## 3. 결과: 유효한 부분

미파싱을 제거하면 신호가 드러납니다.

| 부분집합 | dense | IQ3_XXS |
|---|---:|---:|
| 파싱된 문항만 (각자) | 73/80 = 0.9125 | 67/72 = 0.9306 |
| **양쪽 다 파싱된 64문항** | **61/64 = 0.9531** | **61/64 = 0.9531** |

64문항 페어드 비교: delta +0.0000, CI [−0.0625, +0.0625], McNemar p=1.0000.
불일치 쌍은 2 대 2로 완전 대칭입니다.

**해석의 한계를 분명히 합니다.** 이 64문항은 무작위 표본이 아니라 "두 팔 모두
2048 토큰 안에 추론을 끝낸 문항"이므로 **쉬운 쪽으로 편향**되어 있습니다.
0.9531이 89.2보다 높은 것이 그 증거입니다. 따라서 이 결과는 v22의 결론을
반박하지도 확증하지도 않으며, **양자화가 추론 완주 능력 자체를 훼손하지는
않는다는 정황**으로만 읽어야 합니다.

한 가지 관측이 남습니다. IQ3_XXS의 미파싱이 126 대 118로 8건 많습니다. 정확히 한
팔만 파싱한 문항이 24건이므로, 이 차이가 양자화로 인한 추론 길이 증가인지
샘플링 분산인지는 이 표본으로 구별할 수 없습니다.

## 4. 왜 재실행하지 않았는가

32,768 토큰으로 다시 돌리면 비용이 16배입니다. 이번 실행이 84분 $1.048이었으므로
단순 환산으로 20시간 이상, $15 이상입니다. 잔액을 고려하면 실행 가능하지만,
**같은 질문에 대해 v22가 이미 로그 확률로 답을 냈고** 그 답과 여기서 얻은
정황이 일치하므로 우선순위가 낮다고 판단했습니다.

재실행이 정당한 조건은 다음과 같습니다.

- vLLM 등 연속 배칭 추론 엔진을 도입해 토큰당 비용을 낮춘 뒤
- `reasoning_effort=low`로 사고 길이를 줄여 예산 안에 수렴시키거나
- 문항 수를 줄여(예: 50문항) 32,768 예산을 감당

### 측정하지 않은 것

- **공식 프로토콜 GPQA**: 32,768 토큰으로 측정하지 않았습니다. 따라서
  **IQ3_XXS의 GPQA 점수를 모릅니다.** 89.2와의 비교는 미완입니다.
- **Terminal Bench 2.1**: Claude Code 하네스와 8시간 타임아웃이 필요해
  시도하지 않았습니다. 73.0과의 비교는 미완입니다.
- **미파싱 8건 차이의 원인**: 양자화 효과인지 샘플링 분산인지 미확정.
- **greedy 재현**: `--greedy`로 분산을 없앤 실행을 하지 않았습니다.
- **GGUF와 llama.cpp**: 여전히 미검증. 배포 경로 확인은 열려 있습니다.
