## 2. 이것이 v0.7의 무엇을 말해주는가

v0.7에서 저는 "LTC low3가 4.5% 적은 비트로 동등한 품질"이라고 기록했습니다.
CI가 0을 포함했으므로 "품질 우위 미증명"이라 명시했지만, **"동등"이라는 표현 자체가
과했습니다.** CI가 넓으면 "동등"이 아니라 "판정 불가"입니다.

96문서로 늘리자 진짜 방향이 드러났습니다: **LTC low3는 IQ2보다 약간 나쁩니다.**
차이는 작지만(ppl +2.2%) 통계적으로 실재합니다.

### 지표별로 갈립니다

| 지표 | 우세 | 차이 |
|---|---|---:|
| perplexity | IQ2 | LTC가 +2.2% 나쁨 |
| logit KL | IQ2 | LTC가 +2.6% 나쁨 |
| top-1 일치도 | IQ2 | LTC가 −3.1% 나쁨 |
| router Jaccard | IQ2 | LTC가 −7.0% 나쁨 |
| **margin 비율** | **LTC** | **LTC가 +1.3% 좋음** |

margin만 LTC가 낫습니다. 흥미롭지만 단일 지표이며 CI를 계산하지 않았습니다.
router Jaccard 격차(−7.0%)가 가장 큽니다 — LTC가 MoE 라우팅을 더 교란합니다.

## 3. 설계에 대한 판정

현재까지의 증거를 종합하면:

| 주장 | 증거 | 상태 |
|---|---|---|
| 3:4 제약은 실제 가중치에서 손실 | 자연 0 = 0.313 vs 강제 0.250 | **확립** |
| LTC는 STQ1_0보다 재구성 오차 낮음 | +6.5~7.2% | **확립** |
| LTC는 STQ1_0보다 품질 우세 (동일 비트) | v0.6, 5/5 지표 | **확립** |
| 바이트 형식이 이득 보존, STQ 호환 | v0.4a | **확립** |
| **LTC가 IQ2를 대체할 가치가 있음** | **v0.9: 유의하게 나쁨** | **반증** |
| 민감도 기반 레이어 선택 | v0.8: 최선=최악 | **반증** |

**핵심 결론: LTC는 STQ1_0의 명확한 개선이지만, IQ2_XXS를 대체할 이유는 없습니다.**

9.1% 비트 절약(2.0625 → 1.9688)이 perplexity 2.2% 악화를 부릅니다.
E-ladder 기준으로 나쁜 거래이며, 무릎이 IQ2 바로 아래에 있다는 v0.7 관측과 일치합니다.

### 그렇다면 LTC의 용도는

**STQ1_0을 이미 쓰고 있는 경우에만** 드롭인 교체로 가치가 있습니다. 바이트 호환이므로
기존 STQ1_0 파이프라인에서 코드북만 바꾸면 v0.6이 측정한 품질 개선(ppl −12.9%)을 얻습니다.

**새로 저비트를 도입하는 경우에는 IQ2_XXS가 낫습니다.** 이것이 HY4가 48/77 레이어를
IQ2로 올린 이유를 설명합니다 — 그들도 같은 경계를 발견했을 것입니다.
