# MIX-STQ v0.18 태스크 정확도: LTC의 품질 이득이 태스크 정확도로 이어지지 않습니다

**작성일** 2026-08-30
**결론** **v16 계획의 우선순위 1 게이트 실패.** LTC는 재구성 오차와 perplexity를 개선하지만
MMLU + ARC-Challenge 200문항 페어드 테스트에서 STQ1_0과 **통계적으로 구별되지 않습니다**
(delta = +0.0000, 95% CI [-0.0600, +0.0600], McNemar p = 1.0000).

---

## 1. 이 측정이 필요했던 이유

v0.2–v1.0의 모든 품질 근거는 perplexity / KL / top-1 / margin / router Jaccard였습니다.
v16에서 명시했듯 이들은 **태스크 정확도와 갈라질 수 있습니다.** LTC가 실제로 쓸모가
있는지는 "정답을 더 맞히는가"로만 확인됩니다. 이것이 유일하게 검증되지 않은 고리였습니다.

## 2. 측정 조건

| 항목 | 값 |
|---|---|
| 모델 | `allenai/OLMoE-1B-7B-0924` @ `6d84c48581ece794365f2b8e9cfb043c68ade9c5` |
| 문항 | MMLU 140 + ARC-Challenge 60 = **200** |
| 채점 | 프롬프트 1회 forward, " A".." D" 단일 토큰 log-prob argmax |
| 배분 | layer 0–5 gate_up = STQ 또는 LTC, 그 외 전부 IQ2_XXS |
| 실효 bpw | **양 팔 모두 1.8750** (동일 비트) |
| GPU | Quadro RTX 8000 48 GB (전용, 0% 사전 점유) |
| 통계 | exact McNemar + paired bootstrap 95% CI, 둘 다 일치할 때만 유의 |

세 팔 모두 동일한 200문항, 동일 프롬프트를 보므로 **차이는 코드북뿐입니다.**

*dense를 기준으로 한 부호. 즉 1.875 bpw 양자화는 태스크 정확도를 **12.0%p** 떨어뜨립니다.

## 4. 총계는 같지만 답은 다릅니다

두 팔의 per-item 벡터는 동일하지 않습니다. **20문항은 STQ만, 20문항은 LTC만 맞혔습니다.**
합이 정확히 상쇄되어 총계가 같아진 것입니다. 이것은 LTC가 STQ의 답을 개선한 것이 아니라
**다른 방향으로 흔든 것**임을 뜻합니다.

태스크별로 보면 방향이 반대입니다.

| 태스크 | n | dense | mixed_stq | mixed_ltc | LTC−STQ | 95% CI | p |
|---|---:|---:|---:|---:|---:|---|---:|
| MMLU | 140 | 0.3214 | 0.2500 | **0.3000** | +0.0500 | [−0.1286, +0.0286] | 0.2649 |
| ARC-Challenge | 60 | 0.6333 | **0.4000** | 0.2833 | −0.1167 | [+0.0167, +0.2167] | 0.0654 |

MMLU에서는 LTC가 낫고 ARC에서는 STQ가 낫습니다. 어느 쪽도 두 기준(McNemar와 CI)을
동시에 통과하지 못하므로 **유의하지 않습니다.** 부호가 갈리는 것 자체가
"재구성 오차 −3.8%가 특정 방향의 태스크 이득으로 번역되지 않는다"는 증거입니다.

## 5. v1.0 결과와 모순되지 않습니다

| 지표 | STQ | LTC | LTC 우위? |
|---|---:|---:|---|
| 가중 재구성 오차 (mean_error) | 0.1063 | 0.1023 | 예 (−3.8%) |
| perplexity (v1.0, 별도 측정) | 31.67 | 27.26 | 예 (−13.9%) |
| **태스크 정확도 (본 측정)** | **0.2950** | **0.2950** | **아니오** |

mean_error 0.1063 / 0.1023은 v1.0 `artifacts/mixed.json`의 값과 일치합니다.
같은 양자화 경로가 돌았음을 확인합니다. 따라서 이것은 구현 회귀가 아니라
**지표 간 괴리**입니다. v16이 인용한 SchurQuant(arXiv:2608.15567)의 경고가
우리 데이터에서 재현되었습니다.

## 6. 이 측정이 바꾸는 것

**LTC의 가치 제안은 "동일 비트에서 더 나은 perplexity"까지이며, "더 나은 태스크 정확도"로
확장되지 않습니다.** v16이 정의한 게이트 조건 그대로, 이 결과는 확장 근거가 아니라
정지 신호입니다.

동시에 더 큰 사실이 드러났습니다. **1.875 bpw 자체가 이 모델에서 −12.0%p를 유발합니다**
(0.4150 → 0.2950, p = 0.0160). MMLU 0.2500–0.3000은 4지선다 우연 수준 0.25에 근접합니다.
즉 이 배분점에서는 코드북 선택보다 **비트 예산 자체가 지배적**입니다.
LTC와 STQ를 구분하려는 노력은 이미 무너진 영역 안에서의 비교였습니다.

## 7. 검증 로그

| 주장 | 근거 | 상태 |
|---|---|---|
| 세 팔 모두 동일 200문항 | `items_detail` 200개, 동일 순서 | 확인 |
| 양 팔 동일 비트 | 로그 `bpw 1.8750` 양쪽 | 확인 |
| 양자화가 실제로 적용됨 | 팔당 32개 텐서 per-tensor err 로그 | 확인 |
| v1.0과 동일 경로 | mean_error 0.1063 / 0.1023 일치 | 확인 |
| LTC vs STQ 구별 불가 | McNemar p=1.0, CI가 0 포함 | 확인 |
| dense vs 양자화 유의 | p=0.0160, CI가 0 배제 | 확인 |
| GPU 전용 점유 | 실행 전 `0 MiB, 0 %` | 확인 |

### 측정하지 않은 것

- **다른 모델**: OLMoE 한 종만 측정했습니다. Qwen1.5-MoE 교차 확인은 미실행입니다.
- **더 높은 비트 예산**: 1.875 bpw만 측정했습니다. 2.5–3 bpw에서 두 코드북이
  갈라지는지는 모릅니다. §6의 "비트 예산이 지배적"이라는 관찰을 고려하면
  이 구간이 실제로 의미 있는 비교 영역일 수 있습니다.
- **더 큰 표본**: 200문항에서 페어드 CI 반폭은 ±6.2%p입니다. 3%p 이하의 실제 차이는
  이 표본으로 검출할 수 없습니다. 관측된 불일치 쌍 비율 40/200 = 0.20으로
  McNemar 검정력을 계산하면(alpha 0.05 양측, power 0.80) **3%p 검출에 1,733문항,
  5%p 검출에 616문항**이 필요합니다. 800문항은 CI 반폭이 ±3.1%p가 될 뿐이며
  3%p 차이를 검출하기에는 부족합니다.
- **생성 품질**: 객관식 log-prob만 측정했습니다. 자유 생성은 측정하지 않았습니다.

## 8. 이번 세션에서 고친 결함

측정 자체보다 중요할 수 있는 3건입니다.

| 결함 | 증상 | 원인 | 수정 |
|---|---|---|---|
| `torch_iq2` / `torch_ltc` 미포함 | `eval_mixed` import 실패 | 리포 이관 시 누락 | 두 모듈 커밋 |
| **양자화 무음 무효화** | 세 팔 정확도가 완전히 동일(CI 폭 0) | transformers 4.57에서 `mlp.experts`가 `ModuleList`라 `gate_up_proj`가 None → 전 텐서 skip | pin을 `>=5.0`으로 수정 + `params == 0`이면 예외 |
| 팔 간 OOM | 2번째 `from_pretrained`에서 Killed | 컨테이너 RAM 15 GB, fp16 모델 14 GB | `device_map` 직적재 + 팔별 체크포인트 |

가장 위험했던 것은 두 번째입니다. **오류 없이 "차이 없음"을 출력했고, 그것이
그럴듯한 결론처럼 보였습니다.** CI 폭이 정확히 0인 것이 유일한 단서였습니다.
이제 무효 양자화는 예외로 즉시 중단됩니다.

부수적으로 채점을 문항당 4회 forward에서 1회로 줄였습니다(단일 토큰 선택지에 대해
수학적으로 동일). dense 팔이 15분에서 2분으로 단축되었습니다.

## 10. 다음에 할 일

이 결과가 v16 우선순위를 재정렬합니다.

1. **비트 예산 스윕이 새 우선순위 1입니다.** 2.0 / 2.5 / 3.0 bpw에서 dense 대비
   손실 곡선을 그립니다. −12.0%p는 배포 불가능한 수준이므로, 실사용 가능한
   지점을 먼저 찾아야 LTC 비교가 의미를 갖습니다.
2. LTC vs STQ 재검은 **그 사용 가능한 비트점에서만** 하고, 표본을 600문항으로
   키웁니다(5%p 해상도, 검정력 계산 근거는 위 "측정하지 않은 것" 참조).
   5%p 미만의 코드북 차이는 배포 결정을 바꾸지 않으므로 1,733문항을 요구하지 않습니다.
3. Qwen1.5-MoE 교차 확인은 1–2가 양성일 때만 진행합니다.

**하지 않을 것**: 현재 1.875 bpw에서 LTC 코드북을 더 정교하게 만드는 작업.
이 구간은 이미 우연 수준에 가깝고, v0.8(민감도 배분)과 v0.3e(셀렉터 정교화)에서
확인한 대로 이 축의 개선 여지는 소진되었습니다.
