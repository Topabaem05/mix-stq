## 1. 구현: llama.cpp 스타일 dequantize

v1.2가 남긴 "llama.cpp C 패치" 항목입니다. llama.cpp의 관례를 따랐습니다.

```c
typedef struct {
  uint16_t d;                 // fp16 scale
  uint8_t codes[40];          // 64 groups x 5 bits
} block_ltc1_0;               // 42 bytes, static_assert로 검증

typedef struct {
  int8_t lanes[32][4];        // 코드북: KV 메타데이터에서 복원
} ltc_codebook;

void dequantize_row_ltc1_0(const block_ltc1_0 *blocks, const ltc_codebook *book,
                           float *out, int64_t count);
```

기존 GGUF 양자화 타입과 다른 점은 **코드북 인자 하나**입니다. `ltc_codebook_from_indices`가
32바이트 KV 페이로드를 밑 3 전개로 복원합니다. 블록 파싱 로직은 변경 없습니다.

구현상 까다로운 부분은 **5비트 비정렬 언패킹**입니다. 5는 8의 약수가 아니므로 코드가
바이트 경계를 넘습니다. 2바이트 윈도우를 읽고 시프트하는 방식으로 처리했습니다.

```c
const int bit_offset = group * 5;
uint32_t window = codes[bit_offset >> 3] | (codes[(bit_offset >> 3) + 1] << 8);
const int code = (window >> (bit_offset & 7)) & 0x1F;
```

fp16 → fp32 변환도 subnormal 처리를 포함해 직접 구현했습니다(하드웨어 명령 의존 회피).

## 2. 검증: 비트 단위 완전 일치

실제 OLMoE 가중치 32,768개(128블록), 두 코드북 모두:

| 코드북 | 블록 | 비트 일치 | 최대 오차 | 비영 비율 |
|---|---:|---|---:|---:|
| 학습된 LTC | 128 | **True** | **0.000e+00** | 0.526 |
| STQ1_0 3:4 | 128 | **True** | **0.000e+00** | **0.750** |

**최대 오차가 정확히 0입니다.** fp16 스케일 변환, 5비트 비정렬 언패킹, 밑 3 코드북 복원이
모두 Python 참조와 동일한 부동소수점 결과를 냅니다.

### 비영 비율이 설계 전제를 다시 확인합니다

STQ1_0의 비영 비율이 **정확히 0.750**입니다. 3:4 제약이 4개 중 1개를 0으로 강제하므로
수학적으로 정확히 3/4입니다. 반면 학습된 코드북은 0.526으로 **0을 47.4% 사용**합니다.

이것이 이 연구의 출발점이었던 관찰의 독립적 재확인입니다 — 실제 가중치는 0을 더 원하고
(자연 0 비율 0.313), 3:4는 0.250에서 막고, 학습된 코드북은 그 상한을 풉니다.
C 디코더의 출력에서 이 성질이 그대로 관측됩니다.

## 4. llama.cpp 통합에 남은 작업

이 구현은 **독립 실행 가능한 참조 디코더**입니다. 실제 llama.cpp 통합에는 추가 작업이 필요합니다.

| 항목 | 상태 |
|---|---|
| dequantize 함수 | **완료** (비트 일치 검증) |
| 5비트 언패킹 | **완료** |
| 코드북 KV 복원 | **완료** |
| ggml 타입 등록 (`GGML_TYPE_LTC1_0`) | 미완 |
| `ggml_vec_dot_ltc1_0` (양자화 내적) | 미완 |
| CUDA / Metal 커널 | 미완 |
| `llama_model_loader` KV 조회 배선 | 미완 |

dequantize만으로는 llama.cpp가 모델을 실행할 수 없습니다. 실제 추론에는 양자화된
가중치를 직접 소비하는 `vec_dot`이 필요하며, 그것이 성능의 핵심입니다.
**현재는 정확성만 확립되었고 성능 경로는 미구현입니다.**
