# MIX-STQ v0.5 결과 — 재구성 오차가 품질을 예측하지 못했습니다

**작성일** 2026-08-30
**GPU 지출** $0.0286 (RTX 3090 10.9분, 파괴 완료)
**결론** LTC가 재구성 오차는 6.9% 낮은데 **perplexity는 19% 더 나쁩니다.**

---

## 1. 측정 결과

OLMoE-1B-7B, wikitext-2 test 홀드아웃 16문서 2,669토큰, dense/STQ/LTC 3-arm 쌍 비교.

| 지표 | dense | STQ1_0 | LTC |
|---|---:|---:|---:|
| 가중치 재구성 오차 | — | 0.2792 | **0.2600** |
| perplexity | **12.58** | 8,232 | **9,790** |
| logit KL | 0 | 6.380 | 6.539 |
| top-1 일치도 | 1.000 | 0.035 | 0.048 |
| margin 비율 | 1.000 | 0.346 | 0.308 |
| router top-k Jaccard | 1.000 | 0.402 | 0.434 |

**LTC는 오차 지표에서 이기고 품질 지표에서 집니다.** 재구성 오차 −6.9%,
perplexity +19%, logit KL +2.5%, margin −11%. router Jaccard만 +8% 개선입니다.

이것이 E-ladder와 SchurQuant가 경고한 바로 그 현상입니다:
**로컬 재구성 개선이 종단 품질로 이어진다는 보장이 없습니다.**

---

## 2. 다만 이 실험은 LTC vs STQ 비교로서는 무효입니다

두 arm 모두 **완전히 붕괴**했습니다. top-1 일치도 3.5% / 4.8%는 사실상 무작위이고
perplexity 8,232 / 9,790은 둘 다 언어모델이 아닙니다. **파괴된 모델 두 개의 차이는
의미 있는 신호가 아닙니다.**

### 왜 붕괴했는가 — 제가 설계와 다른 것을 측정했습니다

| 항목 | 값 |
|---|---:|
| gate_up_proj | 4.295B (63.0%) |
| down_proj | 2.147B (31.5%) |
| **1.31 bpw로 양자화한 비율** | **94.5%** |
| 보호된 고정밀도 티어 | **없음** |
| QAT / 학습 | **없음** |

MIX-STQ 설계는 **혼합정밀도**입니다 — HY4 기준 29/77 레이어만 STQ이고 나머지는 IQ2 이상,
down_proj는 IQ3/IQ4, router·norm은 F32입니다. 제 v0.5는 **모든 expert 텐서를 균일하게
1.31 bpw로 내렸습니다.** 이는 설계가 아니라 허수아비입니다.

저장소 자체 증거가 이미 이 결과를 예측했습니다: E-ladder에서 2.30비트 35B MoE가
MMLU 4.51pp를 잃었고, 무릎은 3.5비트 위입니다. 7B를 1.31비트에 균일 배치하면
655배 perplexity 증가는 놀라운 일이 아니라 **예상된 결과**입니다.

### 제 코드의 버그도 하나 있습니다

imatrix는 `mlp.experts` 입력 2048채널입니다. `gate_up_proj`의 마지막 축은
2048(입력 차원)이므로 정렬이 맞지만, `down_proj`의 마지막 축은 1024(expert hidden)입니다.
제 평가 코드는 2048 벡터를 1024로 잘라 썼는데 **down_proj에는 잘못된 importance입니다.**
31.5%의 파라미터가 잘못된 importance로 양자화됐습니다.

## 3. 무엇이 확립되었고 무엇이 아닌가

| 주장 | 상태 |
|---|---|
| 3:4 제약이 실제 가중치에서 손실 (자연 0 = 0.313) | **확립** (v0.2) |
| LTC가 동일 비트에서 재구성 오차를 낮춤 (+6.5~7.2%) | **확립** (v0.3b, v0.4a) |
| 바이트 형식이 이득을 보존 | **확립** (v0.4a) |
| 균일 1.31 bpw PTQ가 7B MoE에서 비가용 | **확립** (v0.5) |
| **재구성 오차 개선 → 품질 개선** | **반증** (v0.5) |
| MIX-STQ 혼합정밀도 레시피의 품질 | **미측정** |

핵심: **LTC는 코덱으로서 유효하지만, 그것이 모델을 더 좋게 만든다는 증거는 없습니다.**
오히려 이 조건에서는 반대 방향입니다.

## 4. 다음에 해야 할 실험 (설계대로)

1. **down_proj importance 수정** — 출력 축 통계를 별도로 수집하거나 down_proj를 보호합니다.
2. **실제 혼합정밀도 배치** — allocator로 일부 레이어만 LTC, 나머지 IQ2_XXS,
   down_proj는 IQ3 이상, router·norm F32. 목표 평균 약 2.4 bpw (HY4 수준).
3. **그 구성에서 3-arm 재측정** — 그때 두 arm이 모두 살아 있으면 비교가 의미를 갖습니다.

**설계 §8의 중단 조건을 재확인합니다.** 원래 조건(자연 0 비율)은 통과했지만,
새로운 중단 조건이 필요합니다: **혼합정밀도 구성에서도 LTC의 품질 이점이 확인되지 않으면
LTC는 재구성 지표만 개선하는 장치이며 배포 가치가 없습니다.**
