# MIX-STQ v0.22 Qwen3.8-27B 교차검증: IQ3_XXS의 무손실 주장이 27B dense에서 재현됩니다

**작성일** 2026-08-31
**정정 2 (v24)** 이 문서의 `mean_error` 값은 **실제 ggml 형식의 오차가 아닙니다.**
사용된 근사 인코더가 IQ3_XXS/IQ2_XXS의 부호 패리티(8값당 7비트, 짝수 패리티)와
서브블록 공유 스케일 제약을 구현하지 않아 실제 오차를 3.5-3.7배 과소평가합니다.
팔 간 상대 비교는 동일 인코더를 통과했으므로 유효하지만, 절대 오차값과
"해석해가 격자 탐색보다 낫다"는 관측은 무효입니다.
`docs/mix-stq-v24-encoder-audit.md` 참조.

**결론** 두 번째 아키텍처에서 핵심 주장이 확인되었습니다. Qwen3.8-27B dense에서
IQ3_XXS(3.0625 bpw)는 fp16과 **통계적으로 구별되지 않습니다**(delta −0.0150,
CI [−0.0150, +0.0450], p=0.5078). 반면 IQ2_XXS는 **유의하게 손실됩니다**
(delta −0.0750, CI [+0.0350, +0.1200], p=0.0007). OLMoE에서 본 "3.06에서 손실이
사라지고 그 아래는 무너진다"가 5.2배 큰 dense 모델에서 그대로 나타납니다.

---

## 1. 이 측정이 필요했던 이유

v18–v21의 모든 정확도 결론은 OLMoE-1B-7B 한 종에 의존했습니다. 그 모델은
dense 정확도가 0.4150, MMLU 0.321로 **4지선다 우연 수준 0.25에서 멀지 않아
양자화 손실을 관측할 동적 범위가 좁았습니다.** IQ3_S가 dense를 넘은 v21 결과도
이 좁은 범위에서 나온 것이라 신뢰도가 제한적이었습니다.

Qwen3.8-27B는 dense 0.8050이므로 이 문제가 해소됩니다.

## 2. 대상 모델 구조

`config.json`과 `model.safetensors.index.json`을 직접 파싱해 확인했습니다.

| 항목 | 값 |
|---|---|
| 모델 | `Qwen/Qwen3.8-27B` @ `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0` |
| 아키텍처 | `Qwen3_5ForConditionalGeneration`, `model_type` `qwen3_5` |
| MoE 여부 | **아니오. dense MLP** (expert 텐서 없음) |
| 레이어 | 64 |
| 어텐션 | 하이브리드 — `linear_attention` 48 + `full_attention` 16 (3+1 반복) |
| hidden / intermediate | 5120 / 17408 |
| MLP 텐서 | gate_proj (17408, 5120), up_proj (17408, 5120), down_proj (5120, 17408) |
| 대상 텐서 수 | **192** (64 레이어 × 3) |
| 멀티모달 | vision tower와 MTP 헤드 존재, **둘 다 양자화 대상에서 제외** |
| 가중치 크기 | 55.56 GB (safetensors 18개) |

5120과 17408 모두 `QK_BLOCK` 256으로 나누어지므로(20블록, 68블록) 잔여 처리가
불필요합니다.

## 5. OLMoE와의 대조: 결론은 같고 신뢰도는 올라갑니다

| 지표 | OLMoE-1B-7B (MoE) | Qwen3.8-27B (dense) |
|---|---:|---:|
| dense 정확도 | 0.4150 | **0.8050** |
| dense MMLU | 0.321 | 0.736 |
| IQ2_XXS vs dense | −0.0400 (p=0.3663, 유의 아님) | **−0.0750 (p=0.0007, 유의)** |
| IQ3_XXS vs dense | +0.0350 (p=0.1671, 유의 아님) | −0.0150 (p=0.5078, 유의 아님) |
| IQ3_XXS vs IQ3_S | 구별 불가 (p=0.6177) | 구별 불가 (p=1.0000) |

두 모델이 **같은 방향**을 가리키지만 27B에서 신호가 훨씬 선명합니다.

- **IQ2_XXS의 손실이 확정되었습니다.** OLMoE에서는 −0.0400이 유의하지 않아
  "평지"로 보였지만, 동적 범위가 넓은 27B에서는 −0.0750이 p=0.0007로 명확합니다.
  v20의 평지 결론은 **OLMoE의 낮은 기준선이 만든 인공물일 가능성**이 큽니다.
- **IQ3_XXS의 무손실은 재현되었습니다.** 두 모델 모두 dense와 구별 불가입니다.
  이것이 이 연구의 가장 견고한 결과입니다.
- **IQ3_S의 추가 이득은 없습니다.** 두 모델 모두 IQ3_XXS와 구별 불가입니다.
  v21에서 IQ3_S가 dense를 이겼던 것(p=0.0347)은 **27B에서 재현되지 않았습니다.**
  OLMoE의 좁은 동적 범위에서 나온 우연으로 보는 것이 타당합니다.

**실무 권고가 단순해집니다: IQ3_XXS 3.0625 bpw.** 5.2배 압축에서 손실이 없고,
IQ3_S로 0.375 bpw를 더 쓸 이유가 없습니다.

## 6. 재구성 오차는 이 모델에서 정확도를 예측합니다

| 팔 | mean_error | 정확도 |
|---|---:|---:|
| IQ2_XXS | 0.0585 | 0.7300 |
| IQ3_XXS | 0.0077 | 0.7900 |
| IQ3_S | 0.0046 | 0.7900 |

오차 7.6배 감소(0.0585 → 0.0077)가 정확도 +6%p를 사고, 추가 1.7배 감소는
아무것도 사지 못합니다. **오차가 임계값 아래로 내려가면 포화합니다.**
v20에서 관측한 순위 역전(혼합 배분)은 여기서 나타나지 않는데, 균일 티어만
측정했기 때문입니다.

## 7. 이번 세션에서 고친 결함

| 결함 | 증상 | 원인 | 수정 |
|---|---|---|---|
| dense MLP 무음 skip | 27B 전체가 양자화되지 않음 | `apply_plan`이 `mlp.experts`만 찾고 `name.split(".")[2]`로 레이어를 읽음 (dense에서는 `"layers"` 문자열) | `layers` 위치를 찾아 인덱스 파싱, dense 분기 추가 |
| 접두사 검사 과엄격 | 어댑터 추가 후에도 전부 skip | safetensors는 `model.language_model.layers...`인데 **런타임 모듈명은 `model.layers...`** (`AutoModelForCausalLM`이 래퍼를 벗김) | 두 접두사 모두 허용 |
| Blackwell 커널 부재 | `CUDA kernel image is invalid` | RTX PRO 6000은 sm_120, torch 2.5.1은 sm_90까지 | torch 2.11.0+cu128 설치 |
| torchvision 불일치 | `operator torchvision::nms does not exist` → transformers 모듈 로딩 실패 | torch만 올려 torchvision 0.20이 남음 | torchvision 0.26.0+cu128로 정렬 |
| 데이터셋 ID 3건 | `wikitext` HfUriError, `github-code` 스크립트 금지, `the-stack-smol` gated | 최신 datasets가 namespace 요구, 스크립트 로더 폐지 | `Salesforce/wikitext`, `code-search-net/code_search_net`로 교체 |

두 번째가 가장 위험했습니다. 어댑터를 추가했는데도 조용히 skip되어 **"양자화했지만
차이 없음"이라는 그럴듯한 오답이 나올 수 있었습니다.** v18에서 추가한
`params == 0` 가드가 이를 예외로 잡아줍니다.

### 측정하지 않은 것

- **IQ2_XS / IQ2_S / IQ3_S 이상**: 27B에서는 2.0625 / 3.0625 / 3.4375 세 점만
  측정했습니다. 2.3125와 2.5625는 미측정이므로 **27B의 2.06–3.06 구간 형태는
  모릅니다.** OLMoE에서 평지였던 것이 27B에서도 평지인지 확인되지 않았습니다.
- **혼합 배분**: 27B에서 시험하지 않았습니다.
- **어텐션·임베딩 텐서**: MLP 192개만 양자화했습니다. 실제 배포는 어텐션
  투영과 임베딩도 양자화하므로 전체 모델 크기 절감은 이 측정보다 큽니다.
- **표본 정밀도**: 200문항, 페어드 CI 반폭 약 ±3–4%p(불일치 쌍이 적어 OLMoE보다
  좁습니다). IQ3_XXS vs IQ3_S의 0.0000은 "차이 없음"이 아니라
  "±3.5%p 안에서 구별 불가"입니다.
- **GGUF 왕복과 C 디코더**: 여전히 파이썬 인코더만 검증했습니다.
- **생성 품질**: 객관식 log-prob만 측정했습니다.

## 10. 다음에 할 일

1. **27B에서 2.3125와 2.5625를 채웁니다.** OLMoE의 평지가 인공물이었다면
   27B의 2.06–3.06 곡선은 계단이 아니라 완만한 경사일 수 있습니다.
   이제 인코더가 빠르고 캐시된 imatrix가 있어 ~$0.2입니다.
2. **GGUF 왕복과 C 디코더 패리티.** 네 티어 모두 실제 배포 경로에서 미검증입니다.
   v12/v13이 LTC에 했던 작업의 반복입니다.
3. **어텐션 투영 포함.** 실제 압축률을 보려면 MLP 외 텐서도 양자화해야 합니다.

**정정할 것**: v20의 "2.06–2.69는 평지" 결론은 OLMoE에 한정됩니다. 27B에서
IQ2_XXS가 유의하게 손실되므로, 그 평지는 **낮은 기준선이 만든 관측 한계**였을
가능성이 높습니다. v21의 "IQ3_S가 dense를 이긴다"도 27B에서 재현되지 않았습니다.
